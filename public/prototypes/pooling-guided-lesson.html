Pooling, step by step

Feature maps carry a lot of numbers. Pooling shrinks them with a simple, fixed rule. Four short stages: why we shrink, how max and average pooling work, how window and stride set the size, and how pooling differs from convolution.

Background

A convolution layer produces feature maps: grids that say how strongly a pattern was found at each position. Early layers keep a lot of spatial detail, so these maps are large, and the network keeps stacking more of them.

Pooling is a local summarization step, not a pattern-learning step. A small window moves across the map and writes one summary value per position. It has no learned weights: max pooling keeps the strongest activation in the window, average pooling keeps the mean.

Because one value stands in for a whole window, height and width shrink, later layers do less work and see a wider area of the original image, and small shifts inside a window stop mattering. Pooling runs on each channel separately, so the number of channels does not change.

Important formulas

Max pooling: each output cell is the largest value inside its window.

Average pooling: each output cell is the mean of the values in its window.

Pooling works channel by channel: height and width shrink, the number of channels stays the same, and there are learnable parameters.

Pros / Cons

Strengths

  • Less to compute. A 2 × 2, stride 2 pool keeps a quarter of the values, so memory and later computation drop.
  • Tolerates small shifts. If a strong response moves within its window, max pooling gives the same output.
  • Wider view for later layers. Each later cell summarizes a bigger area of the image.
  • No parameters. Nothing to learn, so it is simple, fast and easy to explain.

Limitations

  • Throws away detail. Exact positions are lost, which hurts tasks that need precise locations.
  • Can be too aggressive. Large windows or strides shrink the map faster than the network can afford.
  • Fixed rule. Max can ignore moderate but useful signals; average can blur a sharp one. It cannot adapt the way a learned stride-2 convolution can.

Example / Common mistakes

Worked example from this lesson. The 6 × 6 feature map pooled with a 2 × 2 window and stride 2 becomes 3 × 3. With max pooling the centre output is 5, the largest value in its window; with average pooling the same window gives 4.0.

  1. Describing pooling as if it learned a detector. It learns nothing; it compresses a map that convolution already produced.
  2. Thinking pooling mixes channels. It works on each channel separately, so the number of channels is unchanged.
  3. Forgetting the floor in the size formula. When the window does not fit evenly, edge rows and columns are simply skipped.
  4. Assuming pooling makes a network fully shift invariant. It only tolerates small shifts that stay inside a window.
